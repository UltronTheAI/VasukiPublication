# VasukiPublication — Agent Instructions

## 1. PROJECT
- **VasukiPublication** is the public Next.js 16 (App Router, React 19, TypeScript) web reading and publishing platform for books generated by **VasukiSquare**.
- VasukiSquare is the generation engine; VasukiPublication is the public consumer and presentation platform.

## 2. SOURCE OF TRUTH
- `DESIGN.md` is the authoritative source of truth for the **website chrome and user interface**.
- MongoDB documents (`books`, `pages`, `covers`, `ads`) are the authoritative source of truth for **book content and page styles**.
- **No PDF Dependency**: The platform NEVER depends on uploaded PDF files or PDF parsing for rendering.

## 3. NEXT.JS CONVENTIONS
- Always inspect installed documentation under `node_modules/next/dist/docs/` before using framework APIs.
- Utilize Next.js App Router conventions.
- Prefer **Server Components** for data fetching, SEO generation, and non-interactive views.
- Use **Client Components** (`"use client"`) only when state, browser APIs, or event listeners are required.
- Keep all server secrets and database credentials strictly server-only. Never expose them to client components.

## 4. DATABASE & REPOSITORIES
- Use the official MongoDB Node.js driver via the centralized connection layer (`lib/db/mongodb.ts`).
- Always access MongoDB through the repository layer (`lib/repositories/*`). Never execute direct MongoDB queries inside React components or client modules.
- Re-use the cached client promise across serverless and development executions.
- Enforce public publication constraints (`publication.status === "published"` and `publication.visibility === "public"`) on public queries.
- Paginate queries by default (default limit 20, max 50). Never load full book page arrays during catalog or search listings.

## 5. ICONS & VISUAL ASSETS
- Use `lucide-react` for all website UI icons.
- **Never use emojis as UI icons.**
- For books, resolve icons via `lib/vasuki/icon-map.ts` to preserve VasukiSquare's persisted Lucide-compatible icon semantics.

## 6. DESIGN SYSTEM INTEGRATION
- Follow `DESIGN.md` strictly for website UI. Do not invent arbitrary color schemes, generic Bootstrap-like layouts, or unapproved gradients.
- Maintain responsive behavior across mobile, tablet, and desktop breakpoints.
- Ensure strict contrast ratios, semantic typography, and accessible ARIA attributes.

## 7. BOOK RENDERING ISOLATION
- MongoDB structured data is canonical.
- VasukiSquare book pages use their own isolated publication design tokens (`lib/vasuki/render-tokens.ts`) with fixed A4 proportions (1:1.414).
- Do not bleed website global styles into book page containers.
- **Ad Boundary**: Advertisements must NEVER be rendered inside book reading pages. Ads are confined to website discovery spaces.

## 8. SECURITY
- Validate and sanitize all environment variables using `lib/env.ts`.
- Never trust persisted HTML or external feeds blindly. Use `lib/security/html.ts` and `lib/vasuki/sanitization.ts` to strip scripts and event handlers.
- Validate all external URLs with `lib/security/url.ts` before rendering outbound links (`rel="noopener noreferrer nofollow"`).
- Use `timingSafeCompare` for administrative tokens and webhook secrets.

## 9. TESTING & VERIFICATION
- Critical data operations, pagination, search, security validators, and rendering filters must have test coverage outlined in `TEST.md`.
- Ensure `npm run lint` and `npm run build` pass cleanly before submitting any changes.
