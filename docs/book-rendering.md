# VasukiPublication — Book & Cover Rendering Architecture

VasukiPublication renders technical books, rich publication layouts, and cover artwork directly from MongoDB structured data and pre-rendered HTML components without relying on PDF files.

---

## 1. The Zero-PDF Philosophy

Traditional digital publishing platforms force users to download large static PDF files or use sluggish PDF.js canvas viewers. VasukiPublication replaces this entirely with a modern web-native reading experience:

- **Ultra-Fast Streaming**: Book pages load incrementally on demand via indexed MongoDB pagination (`page_number`) and linked-list traversal (`previous_page_id` / `next_page_id`).
- **Semantic DOM Elements**: Text, headings, code blocks, tables, callouts, and diagrams are rendered as true HTML elements, allowing native text selection, searching, copying, and screen reader accessibility.
- **Dynamic Syntax Highlighting & Copying**: Code snippets retain language metadata, line numbers, and instant clipboard copying.
- **Zero PDF Processing Overhead**: No PDF parsing, no font embedding issues, and no heavyweight client-side PDF decoders.

## 2. MongoDB → Reader Flow

```mermaid
flowchart LR
    A[MongoDB 'books' & 'pages'] --> B[App Router /book/slug/read]
    B -->|Initial 2 Pages| C[Server Component SSR]
    C --> D[ReaderContainer Client Shell]
    D -->|Prefetch Requests| E[/api/books/slug/pages?page=N]
    E -->|Page JSON| F[Client Session Cache]
    F --> G[VasukiBookPage Container]
    G --> H[VasukiBlockRenderer]
    G --> I[VasukiHtmlRenderer - Sanitized]
```

1. **Initial Entry**: When a user navigates to `/book/[slug]/read?page=N`, the Server Component fetches the book metadata and only the initial 2 pages from MongoDB (`getBookPages(book.id, initialPage, 2)`).
2. **Client Hydration**: The `ReaderContainer` initializes with the SSR pages pre-populated in its client-side memory cache.
3. **Lazy Prefetching**: As the user reads page $N$, the background prefetcher queries `/api/books/[slug]/pages?page=N+2&limit=2` and populates the cache.
4. **URL Synchronization**: Page state updates seamlessly via `window.history.replaceState` without triggering router re-renders.

## 3. Structured Content vs. Persisted HTML

VasukiSquare persists two representations in each page document:

1. **Structured Data (`Page.content`)**:
   - Machine-readable block models (`HeadingBlock`, `TextBlock`, `CodeBlock`, `TerminalBlock`, `CalloutBlock`, `TableBlock`, `ComparisonBlock`, `TimelineBlock`, `ChecklistBlock`, `StepBlock`, `DefinitionBlock`, `ExerciseBlock`, `QuoteBlock`, `StatisticBlock`, `ChartBlock`, `DiagramBlock`, `TocBlock`, `CopyrightBlock`, `SourceBlock`).
   - Enables high-fidelity rendering, copy-to-clipboard interactions, collapsible solutions, and dynamic responsive layouts.
2. **Pre-rendered HTML (`Page.html`)**:
   - Acts as a high-performance markup cache generated by VasukiSquare's layout engine for legacy or pre-formatted editorial pages.
   - Passed through `lib/security/html.ts` (`sanitizeHtml`) to guarantee absolute protection against stored XSS (stripping `<script>`, `<iframe>`, inline `on*` event handlers, and `javascript:` URLs).

## 4. Style & Design Token Isolation

The website shell and the book reader utilize separate, isolated design languages:

| Context | Design Source | Color Palette / Aesthetic | Scoped Boundary |
| :--- | :--- | :--- | :--- |
| **Website Shell** | `DESIGN.md` | Ink `#171717`, Canvas `#ffffff`, Vercel-inspired hairline borders, mesh gradient accents. | Global Tailwind root |
| **Book Pages** | `lib/vasuki/render-tokens.ts` | Brand Green `#00ed64`, Deep Teal `#001e2b`, Surface `#f9fbfa`, Hairline `#e1e5e8`. | `.vasuki-book-root` |

### Isolation Rules
- All book layout styles, typography rules, and color variables live strictly under `.vasuki-book-root`.
- Website global typography does not bleed into the book page canvas.
- Chapter themes alternate naturally according to editorial conventions (e.g. Chapter 1 light, Chapter 2 dark) or user theme override (`Auto`, `Light`, `Dark`, `Sepia`).

---

## 5. A4 Geometry & Responsive Modes

Every book page adheres to standard A4 proportions (Width to Height ratio of $210 / 297 \approx 0.7071$):

- **Desktop (Spread Mode)**: On wide screens ($\ge 1200\text{px}$), the reader displays a two-page spread view (Left and Right page). Users can toggle between 2-page spread and single-page view.
- **Mobile & Tablet**: Scales proportionally to viewport width while preserving inner block padding and aspect ratio.
- **Zoom Controls**: Users can zoom between $70\%$ and $130\%$ with reset capability.
- **Fullscreen Mode**: Clean focus mode utilizing the browser Fullscreen API with obvious exit controls (`Esc` or toolbar button).

## 6. Icon Compatibility & Lucide Mapping

Persisted VasukiSquare icon names (kebab-case, snake_case, or lowercase) are dynamically resolved via `lib/vasuki/icon-map.ts` and rendered safely using `<VasukiIcon />`:

- **Supported Aliases**: `book-open`, `bookmark`, `file-text`, `file-code`, `layers`, `cpu`, `database`, `server`, `sparkles`, `compass`, `globe`, `code`, `code-2`, `braces`, `terminal`, `square-terminal`, `check-circle`, `check`, `x`, `shield-check`, `shield`, `lock`, `zap`, `activity`, `gauge`, `network`, `workflow`, `lightbulb`, `alert-triangle`, `alert-circle`, `info`, `heart`, etc.
- **Safe Fallback**: Unknown icons deterministically fall back to `Sparkles` or `BookOpen`—preventing broken SVG markup or runtime exceptions.

---

## 7. Navigation & Keyboard Controls

The reader provides intuitive multi-modal navigation:

- **Buttons & Edges**: Left/Right chevron edge buttons on the canvas.
- **Keyboard Shortcuts**:
  - `ArrowLeft` / `PageUp`: Previous page
  - `ArrowRight` / `PageDown` / `Space`: Next page
  - `Home`: Jump to cover (Page 1)
  - `End`: Jump to final page
  - `Escape`: Close ToC drawer or exit fullscreen
- **Touch Swipe**: Swipe left/right gestures for touch screens.
- **Interactive Scrubber**: Direct-scrub visual progress bar at the bottom.
- **Table of Contents**: Slide-over drawer with search filtering, chapter badges, and instant jump links.

---

## 8. Monetization & Content Integrity Boundary

**ABSOLUTE RULE**:
- **Zero Ads Inside Reader**: Advertisements are strictly prohibited from appearing within `/book/[slug]/read`.
- No banners, sidebar ads, modal ads, or sponsored pages are rendered in the reader tree.
- Ads remain confined strictly to discovery spaces (home banner/sidebar and saved books).
